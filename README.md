Visit with Us — Tourism Package Purchase Prediction (MLOps)
This project predicts `ProdTaken` (0 = no purchase, 1 = purchase) using customer and sales-interaction attributes. It implements data validation, preparation, hyperparameter tuning with MLflow tracking, model artifact versioning, GitHub Actions CI/CD, and a Streamlit app.

1. Add the dataset
Copy the course-provided `tourism.csv` into `tourism_project/data/tourism.csv`. The registration script validates the expected columns and prints dataset shape, types, missing values, and target distribution. If the dataset uses different column names, compare it with the course data description and adjust `EXPECTED_COLUMNS` in `data_register.py` only when appropriate.
Expected target: `ProdTaken`. `CustomerID` is removed because it is an identifier, not a useful model feature.
2. Run locally (optional)
Use Python 3.11 in a virtual environment:
```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r tourism_project/requirements.txt
python tourism_project/model_building/data_register.py
python tourism_project/model_building/prep.py
python tourism_project/model_building/train.py
streamlit run tourism_project/deployment/app.py
```
The preparation script saves split CSV files under `artifacts/`. The training script performs Random Forest grid search using stratified cross-validation, logs best parameters and test metrics to MLflow (`./mlruns`), and saves the fitted preprocessing/model pipeline and metadata under `tourism_project/deployment/`.
3. Push to GitHub and run the workflow
Create a GitHub repository (public is convenient for Streamlit Community Cloud).
Upload this folder's contents to the repository root, including `.github/`.
Ensure `tourism_project/data/tourism.csv` is committed.
Open Actions → Tourism MLOps Pipeline. It runs on pushes to `main` or manually via Run workflow.
Review the register, prep, and model-training job logs. The split files are passed between jobs as a workflow artifact; MLflow logs are also uploaded as an artifact.
The workflow commits `tourism_model.joblib` and `model_metadata.json` back to `main` using the repository's `GITHUB_TOKEN` permission. Model-only paths are excluded from the push trigger to avoid retraining loops.
The workflow does not require a personal access token. Repository Actions permissions must allow the workflow to write contents (Repository Settings → Actions → General → Workflow permissions → Read and write permissions).
4. Deploy on Streamlit Community Cloud
Confirm the latest workflow succeeded and the trained model exists in `tourism_project/deployment/`.
Go to https://share.streamlit.io and choose Create app.
Select your repository and `main` branch.
Set Main file path to `tourism_project/deployment/app.py`.
Deploy. The app dependencies are in `tourism_project/deployment/requirements.txt`.
Open the app URL and test a prediction.
